# Upgrade from 3.1 to 4.0

## Requirements

- PHP 8.4 minimum
- Symfony 7.4
- Doctrine ORM 3

## Update the dependencies

```diff
- "austral/security-bundle": "^3.1"
+ "austral/security-bundle": "^4.0"
```

All `austral/*` packages must be upgraded to `^4.0` at the same time.

## Breaking changes

### Sources and configuration

The sources are in `src/`. The classes of the application are set in the bundle configuration instead of the
parameters `austral.entity.*.class` and `austral.resolve_target_entities.security`:

```yaml
# config/packages/austral_security.yaml
austral_security:
    entities:
        user:   App\Entity\Austral\SecurityBundle\User
        role:   App\Entity\Austral\SecurityBundle\Role
        group:  App\Entity\Austral\SecurityBundle\Group
```

These are the defaults: an application that keeps the skeleton classes has nothing to add. The bundle
resolves `UserInterface`, `RoleInterface` and `GroupInterface` to these classes in
`doctrine.orm.resolve_target_entities`.

### Database

Three changes, in this order. **Rename the column before generating the migration**: a migration generated by
`doctrine:migrations:diff` on the old column drops `role_id` and creates `group_id`, and the users lose their
groups.

1. Rename the join column of the groups (MySQL 8 / MariaDB 10.5 and PostgreSQL), in a migration created with
   `doctrine:migrations:generate`:

   ```sql
   ALTER TABLE austral_security_user_group RENAME COLUMN role_id TO group_id;
   ```

2. Then generate the rest with `doctrine:migrations:diff` and check it. It drops `salt` and
   `forgot_password_token` and adds the columns of the password reset:

   ```sql
   -- MySQL
   ALTER TABLE austral_security_user
     DROP salt,
     DROP forgot_password_token,
     ADD password_reset_selector VARCHAR(32) DEFAULT NULL,
     ADD password_reset_hash VARCHAR(128) DEFAULT NULL,
     ADD password_reset_expires_at DATETIME DEFAULT NULL;
   CREATE UNIQUE INDEX UNIQ_... ON austral_security_user (password_reset_selector);
   ```

   The diff may also rename the indexes and foreign keys of `austral_security_user_group`: keep them.

3. Run the migrations.

### Passwords

`MigratePasswordHasher` and the salt are removed. The users are hashed with the hasher of `security.yaml`:

```diff
 password_hashers:
-    migrate_austral_hasher:
-        id: austral.security.hasher.migrate_password
-    App\Entity\Austral\SecurityBundle\User:
-        algorithm: sodium
-        migrate_from:
-            - migrate_austral_hasher
+    App\Entity\Austral\SecurityBundle\User: 'auto'
```

The passwords saved by 3.1 (sodium) are still valid with `auto`, and are rehashed at the next login. A password
hashed by 3.0 (bcrypt of the password and the salt) is no longer valid: the user resets it with the "forgotten
password" link of the login page, or an administrator sets a new one:

```bash
php bin/console austral:security:user --email=jane@austral.dev
```

The plain password is hashed when the user is saved by the entity manager (`updateUser()`, `update()`), not by
`UserEntityManager::updatePassword()`, which is removed.

### security.yaml

The skeleton `Resources/config/squelette/security.yaml` is removed: the firewall belongs to the application,
the one of the back office is documented by admin-bundle. Keep in `config/packages/security.yaml`:

- the provider `austral.security.user_provider` and `user_checker: austral.security.user_checker` (a disabled
  user cannot log in) on the firewall
- the hasher `auto` (see Passwords)
- remove `enable_authenticator_manager`, replace `IS_AUTHENTICATED_ANONYMOUSLY` by `PUBLIC_ACCESS`

For the login link, add `login_link` to the firewall and set its name:

```yaml
austral_security:
    login_link:
        firewall: austral_admin
```

`security.authorization_checker` is no longer replaced: a root user is granted everything by the `RootVoter`
(priority 1000), the other users go through the usual voters.

### Moved to admin-bundle and to the bridge

The login page and the screens belong to admin-bundle, the admin modules to the bridge of this bundle:

| 3.1 | 4.0 |
|---|---|
| `Controller\AuthenticatedController`, `Resources/config/routes.yaml` | admin-bundle (routes `austral_admin_security_*`) |
| `Resources/views/login.html.twig`, `Layout/*`, `List/Components/avatar.html.twig` | admin-bundle |
| `Admin\UserAdmin`, `AdminUserAdmin`, `GroupAdmin`, `RoleAdmin` | `Bridge\Admin\UserAdmin`, `AdminUserAdmin`, `GroupAdmin`, `RoleAdmin` (admin-bundle 4 API) |
| `Resources/config/austral_admin.yaml` (parameter `austral_admin.modules.security_bundle`) | `Bridge/Admin/austral_admin.yaml`, configuration `austral_admin.modules.security` |
| parameters `austral.admin.modules.security_bundle.*.enabled` | `austral_admin: { modules: { security: { children: { users: { enabled: false } } } } }` |
| `Form\Austral\UserForm` | the form of `Bridge\Admin\AbstractUserAdmin` (form-bundle 4) |
| `Listener\DashboardListener` | the tiles of the dashboard of admin-bundle |

The paths and the roles of the modules do not change. The users, administrators and roles cannot be duplicated
any more.

### Removed or changed classes and methods

| 3.1 | 4.0 |
|---|---|
| `getSalt()`, `setSalt()` | removed |
| `getForgotPasswordToken()`, `setForgotPasswordToken()` | `PasswordResetManager` (`austral.security.password_reset`) |
| `UserEntityManager::updatePassword()` | saving the user (`PasswordListener`) or `austral.security.password_updater` |
| `UserEntityManager::deleteUser($user)` | `delete($user)` |
| `UserProvider::loadUserByUsername()` | `loadUserByIdentifier()` (email, username or id) |
| `RoleEntityManager::selectRoles()`: `Collection` | `array<string, RoleInterface>` indexed by role |
| `getTypeUser(): ?string` | `string`; `setTypeUser()` refuses an unknown type |
| `Repository\Base\BaseUserEntityRepository` | `Austral\EntityBundle\Repository\EntityRepository` |
| `Listener\EntityManagerListener` (`austral.security.entity.manager.listener`) | `Listener\PasswordListener` |
| `Security\Authorization\AuthorizationChecker` | `Security\Voter\RootVoter` |
| `Security\Hasher\MigratePasswordHasher` | hasher `auto` |
| `DependencyInjection\Compiler\DoctrineResolveTargetEntityPass` | configuration `austral_security.entities` |
| service `austral.security.user` (command) | `Austral\SecurityBundle\Command\UserCommand` (same name `austral:security:user`) |

A custom user class implements `Austral\Contracts\File\CropperInterface` (through the base `User`) instead of
`Austral\EntityFileBundle\Entity\Interfaces\CropperInterface`.

### Sessions

The user stored in the session changes: the users are logged out once after the upgrade.
